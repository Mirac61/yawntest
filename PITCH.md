# lazytest — Pitch & Build Brief

> Working title. Check for name collisions before publishing.

**One line:** A local, offline CLI that reads your Go code, recognizes common code patterns, and writes the boring tests for you.

**For:** developers who know they should write tests but don't want to write the same handler / round-trip / edge-case tests for the hundredth time.

---

## 1. Problem

Most tests in a typical Go backend are predictable:

- an HTTP handler should reject garbage input with a 4xx, not a 5xx or a panic,
- a struct with JSON tags should survive encode → decode,
- a pure function should not panic on edge inputs and should be deterministic,
- a validation function should reject empty / huge / weird input.

Developers skip these because they are tedious, not because they are hard. Existing tools don't close the gap:

- `gotests` (cweill/gotests) generates table-driven **skeletons** with empty tables.
- AI test generators need an API, cost money, are non-deterministic and often encode current (buggy) behavior as "expected".

**lazytest fills in the cases**, deterministically, without AI, and only asserts things that are always true.

## 2. Core rule (do not break)

> lazytest never invents expected business values.

It only generates assertions that hold regardless of business logic:

- no panic,
- invariants (round-trip equality, determinism, `end >= start`, sum of parts == total),
- protocol rules (bad input → 4xx, never 5xx),
- or a clearly marked `// TODO(lazytest): expected value` with `t.Skip` so the user decides.

If a generated test fails on the user's current code, that is a **finding** (potential bug), reported as such. Never silently delete or "fix" it.

## 3. Principles

- **Offline, deterministic:** same input → byte-identical output. No network, no AI.
- **Go standard library first:** `go/parser`, `go/ast`, `go/format`, `text/template`, `os/exec`. `golang.org/x/tools` is the only allowed exception, and only if type information is genuinely required.
- **Explainable:** every generated test and every finding says which pattern triggered it and why.
- **Non-destructive:** never touch user-written test files. Generated code lives in its own files.
- **Lazy-friendly:** zero config for the default case.

## 4. CLI

```bash
lazytest [path]            # generate tests for functions without tests (default: .)
lazytest --changed         # only functions changed since last commit (git diff HEAD)
lazytest --check           # touch nothing, report what's missing
lazytest --run             # generate, then run go test on generated files and report findings
lazytest --force           # regenerate existing lazytest files
lazytest --json            # machine-readable output
```

Example output:

```text
internal/api/tasks.go
  ✓ CreateTask        http-handler     + 3 tests
  ✓ Task              json-roundtrip   + 1 test
  ✓ ParseDuration     pure-func        + fuzz (14 seeds)
  ? NormalizeTitle    validation       + 4 cases (2 expected values TODO)
  ⚠ CreateTask        finding: invalid JSON body returns 500 (expected 4xx)

Generated 4 files, 9 tests. 1 finding.
```

## 5. Output conventions

- One generated file per source file: `foo.go` → `foo_lazytest_test.go`, same package.
- File header: `// Code generated by lazytest. Edit freely; rerun with --force to regenerate.`
- Each test carries a comment naming the pattern: `// lazytest: http-handler / bad-json`.
- Output is `gofmt`ed. Generated code must compile (`go vet` clean).
- Table-driven style, `t.Run` subtests, `t.Parallel()` where safe.

## 6. v1 Patterns

Detection is syntactic (AST + names) unless noted. Each pattern = detector + template.

| # | Pattern | Detect | Generated tests |
|---|---|---|---|
| 1 | **http-handler** | `func(http.ResponseWriter, *http.Request)` (func or method), or `http.HandlerFunc` values | `httptest`: no panic on empty request; if body is decoded as JSON → invalid JSON gives 4xx; empty body gives 4xx; response never 5xx on bad input |
| 2 | **json-roundtrip** | exported struct with `json:"…"` tags | populate fields with non-zero values per type, `Marshal` → `Unmarshal`, `reflect.DeepEqual` |
| 3 | **pure-func** | exported func, only basic-typed params (int, float, string, bool, time.Time, slices of those), no receiver state, no I/O imports used in body | Go native fuzz test (`testing.F`) seeded with edge values; asserts no panic + determinism (call twice, compare) |
| 4 | **validation** | name matches `Validate*`, `IsValid*`, `Check*`, or returns `error`/`bool` with a single string/struct param | cases: empty, whitespace, very long (10k), unicode/emoji, nil/zero struct; expected result marked TODO + `t.Skip` unless obvious (empty → error) |
| 5 | **untested-error-paths** (`--check` only) | run `go test -coverprofile`, map uncovered lines that are `return …, err` / `return err` | report only, no generation |

### Edge value seeds (shared)

- int: `0, 1, -1, math.MaxInt, math.MinInt`
- float: `0, -0.0, 0.1, -1, 1e308, math.NaN(), math.Inf(1)`
- string: `"", " ", "a", strings.Repeat("x", 10000), "ünïcødé", "😀", "\x00", "' OR 1=1 --"`
- time: Unix 0, leap day `2024-02-29`, DST switch `2026-03-29 02:30 Europe/Berlin`, `23:59:59`, `00:00:00`, year 9999
- slice: nil, empty, one element, 10k elements

## 7. Domain hints (v1.1, after the 5 patterns work)

Keyword + type detection adds domain-specific invariants and findings:

- **money:** names `amount|price|total|cost|balance|fee` + `float32/float64` → finding "float used for money"; invariant: splits sum to total.
- **dates:** `time.Time`, names `start|end|due|deadline` → `end >= start`; DST/midnight seeds; finding: `time.Now()` without explicit location.
- **auth:** names `password|token|secret|session` → finding: comparison with `==` instead of `subtle.ConstantTimeCompare`.

## 8. Architecture

```text
cmd/lazytest/          main.go, flag parsing
internal/scan/         walk dirs, skip vendor/testdata/generated, parse files
internal/detect/       one file per pattern: Detect(*ast.File) []Match
internal/gen/          templates per pattern, render + go/format
internal/run/          go test / coverprofile execution, map failures to findings
internal/report/       text + JSON output
```

Keep it flat. No plugin system, no interfaces until a second implementation actually exists.

## 9. Milestones

1. **M1:** scan + detect patterns 1–4 + `--check` text report (no generation yet).
2. **M2:** generation for json-roundtrip and pure-func (easiest, fully automatic).
3. **M3:** http-handler and validation generation.
4. **M4:** `--run` (findings), `--changed`, pattern 5 (coverage-based error paths).
5. **M5:** domain hints (money, dates, auth).

Each milestone ships with its own tests: golden-file tests (input `.go` in `testdata/` → expected generated output).

## 10. Definition of done (v1)

- `lazytest ./some/go/project` runs offline, finishes in seconds on ~20k LOC.
- All generated files compile and are `gofmt`/`go vet` clean.
- Running twice produces identical output.
- User-written test files are never modified.
- At least one real finding on a real project (test target: a Go + SQLite backend with HTTP handlers and date logic).

## 11. Non-goals

- No AI / LLM integration.
- No languages other than Go in v1 (TypeScript later).
- No guessing business-correct expected values.
- No automatic code fixes.
- No coverage percentage of its own; use `go test -cover` output when needed.
- No GUI, no IDE plugin in v1.
